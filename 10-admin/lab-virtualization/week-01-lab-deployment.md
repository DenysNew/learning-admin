# Week 01 — Развёртывание лабораторной инфраструктуры

## Цель недели

Полностью развернуть и задокументировать лабораторную среду VirtualBox:

- установка виртуальных машин
- настройка сетевой архитектуры
- настройка статической и динамической адресации
- настройка DHCP
- проверка маршрутизации
- тестирование доступа в интернет
- фиксация артефактов

---

# 1. Используемая платформа

## Гипервизор

- Oracle VirtualBox

## Сетевые режимы

- Adapter 1: NAT (доступ в интернет)
- Adapter 2: Internal Network (lab-net)

---

# 2. Развернутые виртуальные машины

| VM | ОС | Роль | lab-net IP | Тип IP | NAT |
|----|----|------|------------|--------|-----|
| kali-attacker01 | Kali Linux | Attacker | 10.10.10.50 | Static | DHCP |
| srv-dc01 | Windows Server 2022 | Domain Controller / DNS / DHCP | 10.10.10.10 | Static | DHCP |

---

# 3. Сетевая архитектура

## Сегмент 1 — NAT

- сеть: 10.0.2.0/24
- шлюз: 10.0.2.2
- выдаётся VirtualBox
- используется как default route

Назначение:
- обновления
- установка пакетов
- доступ к интернету

---

## Сегмент 2 — Internal Network (lab-net)

- сеть: 10.10.10.0/24
- полностью изолирована
- используется для:
  - Active Directory
  - тестирования атак
  - взаимодействия между VM

---

# 4. Политика адресации

## Статические IP

- 10.10.10.10 — srv-dc01
- 10.10.10.50 — kali-attacker01

## DHCP-пул

- 10.10.10.100 – 10.10.10.200
- выдаётся Windows Server (роль DHCP)

---

# 5. Маршрутизация

Принцип:

- Default Gateway указывается только на NAT-интерфейсе
- Внутренний интерфейс (lab-net) без gateway
- DNS внутри лаборатории — 10.10.10.10

---

# 6. Проблемы и их решение

## Проблема 1 — DHCP не выдавал IP после перезапуска

Причина:
- конфликт управления интерфейсами NetworkManager / ifupdown

Решение:
- корректная настройка NetworkManager
- проверка autoconnect
- перезапуск служб
- тест reboot

---

## Проблема 2 — Отсутствие default route

Причина:
- gateway был указан на внутреннем интерфейсе

Решение:
- удалён gateway с lab-net
- default route оставлен только через NAT

---
